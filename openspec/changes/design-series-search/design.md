## Context

Сейчас презентер каталога получает `/shows.json` при открытии страницы, а данные содержат единственный `genre`. Поиск требует отдельной выдачи для каждого запроса и массива жанров. Изменение стартового поведения отражено в дельте `project-setup`.

## Goals / Non-Goals

- Визуальный эталон — [«Season One»: экраны, компоненты и токены](../../../docs/design/README.md). Имена компонентов в эталоне и библиотеке должны совпадать.
- Настольная сетка и мобильные строки представляют одни и те же данные. Экран подробностей, избранное и просмотр видео в это задание не входят.

## Decisions

1. **Поиск по мере ввода.** Поле остаётся одним и тем же элементом при переходе от пустого состояния к выдаче, чтобы сохранить фокус и позицию курсора. После короткой паузы (300 мс) отправляем строку без крайних пробелов; пустой строке соответствует отсутствие запроса. Альтернатива с кнопкой отправки добавляет шаг.
2. **Полная выдача до нарезки на тройки.** Нормализуем ответ в `id`, название, массив жанров и необязательные год и постер. Сохраняем порядок источника. Презентер строит набор уникальных жанров по полному ответу; затем фильтрует карточки и делит результат на группы по три. Нарезка до фильтрации скрыла бы жанры следующих страниц.
3. **Один список для двух способов навигации.** Номер страницы — переход к началу группы. Если группа ещё не открыта, добавляем недостающие группы до неё. Пересечение нижней границы при прокрутке открывает только следующую группу. Выделенный номер соответствует верхней видимой группе, а у конца документа — последней. При переходе по номеру подводим группу под панель навигации; при ручной прокрутке не перемещаем фокус.
4. **Состояния на уровне компонентов.** Первая загрузка занимает место выдачи; последующая показывает только строку под имеющимися карточками, если ожидание действительно есть. Ошибка запроса оставляет поле и повтор. Карточка с отсутствующими метаданными сохраняет место в сетке.

## Risks / Trade-offs

- Поздний ответ может вернуть старую выдачу → привязать результат и ошибки к текущему запросу; очистка сразу снимает жанр, страницы и состояния.
- Высокий экран может сразу вместить несколько групп → начальное открытие показывает только первую; нижнюю границу активирует прокрутка вниз. Повторное событие не дублирует группу.
- Доступен только постраничный API → для достоверного набора жанров и числа страниц нужен полный ответ либо агрегированные данные источника. Не считать первую серверную страницу всей выдачей.
- Много страниц или жанров → переносить теги, а в навигации оставлять первую, последнюю и ближайшие к текущей страницы. Номера должны оставаться доступными с клавиатуры.
