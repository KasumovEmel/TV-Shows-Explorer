## ADDED Requirements

### Requirement: Читаемость управляющего кода

Форматирование в редакторе и через CLI MUST разделять вызовы хуков пустыми строками, отделять `return` пустой строкой от предыдущей инструкции в том же блоке и оформлять тела условий и циклов блоками. Линтер MUST отклонять сокращённые блоки и вложенные тернарные выражения.

#### Scenario: Автоформатирование

- **WHEN** между соседними инструкциями стоит вызов хука, внутри которого написано `if (ready) run();`
- **THEN** форматтер отделяет вызов пустой строкой от соседних инструкций и помещает `run();` на отдельную строку внутри фигурных скобок
- **AND** результат одинаков при сохранении, при запуске `pnpm format` и при повторном форматировании

#### Scenario: Условия

- **WHEN** разработчик вкладывает тернарный оператор в другой
- **THEN** Oxlint сообщает об ошибке, а одиночное выражение `ready ? a : b` разрешено

### Requirement: Асинхронные операции

Oxlint MUST проверять использование промисов и наличие обработки ошибок при HTTP-запросе.

#### Scenario: Вызов без ожидания

- **WHEN** код оставляет промис без обработки или передаёт асинхронную функцию обработчику, ожидающему `void`
- **THEN** проверка сообщает об ошибке; намеренный запуск в фоне можно обозначить оператором `void`

#### Scenario: Ошибка запроса

- **WHEN** общий HTTP-клиент отправляет запрос через Axios
- **THEN** проверка требует дождаться запроса внутри `try` с соответствующим `catch`

#### Scenario: Новый эндпоинт

- **WHEN** эндпоинт вызывает `request()` из `@shared/utils/request`
- **THEN** проверка разрешает вызов без локального `try/catch`
- **WHEN** код приложения за пределами общего клиента подключает клиент Axios или использует браузерный `fetch` или `XMLHttpRequest`
- **THEN** Oxlint указывает использовать `request()`, даже если вызов обёрнут в `try/catch`
- **AND** типы Axios и именованная проверка `isAxiosError` доступны обработчику ошибок
