# Какие правила относятся к SA, а какие — к TV Shows Explorer

Раньше комплект SA оставлял проекту выбор, где разместить первый helper. Теперь у правила один ответ для любого проекта: `logic/helpers/normalizeQuery.ts` с первого файла. Так же размещаются Tasks, хуки, утилиты, операции API и внутренние типы. [Структура SA](../apps/web/rules/sa-structure.md)

## Что перешло в общие правила SA

| Решение          | Что делает агент                                                                                                                                                                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Область владения | Кладёт частный компонент у потребителя, общий код — у ближайшего общего владельца. Рядом с View держит основной Presenter, публичные типы и стили.                                                                                                        |
| Категория файла  | Для первого файла сразу создаёт папку нужной категории. Например, чистая нормализация — `logic/helpers/normalizeQuery.ts`, сценарий выбора жанра — `logic/tasks/selectGenre.ts`.                                                                          |
| Имена            | Называет Task глаголом в camelCase. Одна Task, helper или util занимает одноимённый файл. Каждая собственная булева переменная, параметр или поле начинается с `is`, например `isSelected` и `isLoading`. [Именование SA](../apps/web/rules/sa-naming.md) |
| Границы модулей  | Обращается через публичные экспорты. Данные передаёт потомкам через параметры, события возвращает общему владельцу через callbacks.                                                                                                                       |
| Контракты        | Хранит тип у владельца контракта, объединяет несколько собственных аргументов в именованный объект и сохраняет сигнатуру внешнего API на границе.                                                                                                         |
| Данные           | Описывает Entity предметным типом. Store вводит для общего изменяемого состояния. Локальные состояние, фокус и обработчики принадлежат Presenter.                                                                                                         |
| Интеграции       | Адаптер отвечает за протокол и внешний формат. Task выполняет сценарий и возвращает предметный результат. В тесте можно подменить транспорт, часы или хранилище.                                                                                          |

## Что определяет проект

TV Shows Explorer выбирает Orval и общий `request<T>()` для HTTP, i18next для текстов и View Transitions для переходов. Продукт задаёт критерии поиска, поведение избранного, обработку HTTP 429, токены и требования к доступности. Эти детали агент находит в [архитектуре клиента](../.agents/rules/architecture.md), [правилах проекта](../.agents/rules/project.md) и [дизайне компонентов](design/components.md).

## Требования за пределами клиентской SA

| Область           | Что уже действует в проекте                                                                                                                                                                                                                                                                                                                        |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сборка и проверки | Строгий TypeScript, React StrictMode, Rsbuild, закреплённые версии инструментов. После изменения выполнить `pnpm format` и `pnpm check`. Orval-код генерируется из контракта, TypeScript и `pnpm api:check` проверяют результат.                                                                                                                   |
| Оформление        | Oxfmt и скрипты проекта упорядочивают импорты, хуки и отступы. Oxlint требует блоки для условий, проверяет вложенные тернарные выражения, промисы и обработку ошибок HTTP. Лимит 120 строк существовал в обоих комплектах. Здесь Git-список текстовых файлов проверяет скрипт, учитывая пустые строки и комментарии, с явными исключениями.        |
| Сервер            | Модули `catalog/`, `favorites/`, `health/` предоставляют публичный `index.ts`. Hono-контекст хранит зависимости, HTTP-операция имеет одноимённый обработчик, сценарий вызывается вне Hono. Контракт принадлежит `packages/contracts/`, внешний HTTP — адаптеру TVmaze. В тестах используют отдельные объекты в памяти, подменяют транспорт и часы. |
| Процедура работы  | Локальный корневой `AGENTS.md` требует прочитать правила в `.agents/rules/`, использовать RTK на машине автора и оформлять новые домашние задания через OpenSpec. Текущее поведение описывается в `openspec/specs/`, работа над изменением — в `openspec/changes/`. Корневой файл и OpenSpec исключены из Git в этом репозитории.                  |
| Секреты           | Проверять подготовленные изменения и отправляемые коммиты. Правило распространяется на Git-историю, сообщения, названия веток, PR, примеры и скриншоты. Данные доступа к инфраструктуре поступают из секретов окружения, их нельзя публиковать в логах, артефактах и кеше.                                                                         |
| Релиз             | Проверить DNS, ключ хоста, firewall, VPN, порты и TLS. Релиз запускается вручную или тегом `release-*`. Новый процесс начинает с пустых списков и кеша каталога. После выкладки проверяют поиск, избранное и изоляцию сессий, после тестового отката — ревизии клиента и API.                                                                      |

Источники: [сервер](../.agents/rules/server-architecture.md), [релиз](../.agents/rules/deployment.md), [команды](../README.md), [проверка длины файлов](../scripts/check-lines.mjs), [область проверки](../scripts/project-files.mjs), [линтер](../.oxlintrc.json), [исключения Git](../.gitignore).

## Какие правила давать агенту

- При добавлении файла начинай с общего правила SA. По назначению функции оно даёт путь и имя: `logic/tasks/selectGenre.ts`.
- Для проектной интеграции открой локальную инструкцию. Например, общий принцип определяет границу API, а TV Shows Explorer задаёт конкретный HTTP-клиент.
- На ревью проверяй владельца состояния и направление импортов по коду. Форматирование, типы и соответствие генерации проверяй командами репозитория.
