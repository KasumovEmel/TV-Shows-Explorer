# Публикация Season One

Перед первым включением сверить A- и AAAA-записи сайта с адресами VPS и проверить ключ хоста SSH. На сервере проверить занятые порты, firewall, конфигурацию nginx и путь к Node 24.22.2 или новее. Выполнить проверку соединения через действующий VPN до и после переключения.

Если nginx обслуживает TCP 80, а TCP 443 свободен, добавить отдельный HTTP virtual host для этого домена с webroot ACME, проверить `nginx -t` и выполнить reload. Выпустить сертификат HTTP-01 через этот webroot. Подключить `nginx.conf` и открыть согласованный TCP-порт после проверки конфигурации. Если 443 занят действующим TLS-прокси, добавить virtual host в его конфигурацию. Если 443 занят непосредственно VPN, выбрать проверенный свободный HTTPS-порт и подходящий challenge. Указать итоговый origin в переменной Actions `SITE_URL`.

## Первоначальная настройка

1. Создать системного пользователя `season-one`. Создать `/srv/season-one/{data,releases,backups}`. Пользователю API дать запись в data, пользователю деплоя — управление релизами, резервными копиями и переключением current, а также доступ для SQLite backup. Разрешить nginx читать web в каталогах релизов. Backups и data должны быть доступны только сервисным пользователям.
2. Установить SQLite CLI и unit `season-one.service`, сверить пути Node и порт, выполнить `systemctl daemon-reload` и `systemctl enable season-one`. Дать пользователю SSH право выполнять `sudo -n systemctl restart season-one.service` и `stop season-one.service`.
3. В окружении GitHub Actions `production` создать секреты `VPS_HOST`, `VPS_USER`, `VPS_PORT`, `VPS_SSH_KEY` и `VPS_KNOWN_HOSTS`. Для `VPS_KNOWN_HOSTS` использовать запись known_hosts с проверенным ключом хоста. Публичный HTTPS-адрес сайта указать в переменной `SITE_URL`.
4. Запустить Release вручную на выбранной ревизии или отправить тег `release-*`. Приложение и API переключаются ссылкой current. SQLite и её согласованная резервная копия находятся вне релиза. Изменения схемы должны сохранять совместимость с предыдущим API при откате.
5. Проверить ранее сохранённую карточку после релиза и простоя, вход из другого профиля и поиск Breaking Bad. Для приёмки отката использовать изолированный стенд с предыдущим релизом и кандидатом, у которого health возвращает ошибку. Сверить SHA сайта и API после автоматического возврата, данные сессии и VPN.
