# Архитектура приложения

Для изменения клиента открой [указатель правил SA](../../apps/web/AGENTS.md) и правило затронутого слоя.

## Роли VIPER

- **View** (`Name.tsx`) рисует JSX по пропсам. Если нужны состояние или обработчики, получает их из `usePresenter(props)`.
- **Presenter** (`usePresenter.ts`) готовит данные и обработчики для View, запускает эффекты и выполняет переходы. Состояние UI держи в Presenter ближайшего общего владельца. Храни текущий ответ API в состоянии React.
- **Interactor** (task) реализует действие пользователя или правило продукта, например выбор жанра и сброс страницы. Task вызывается вне React, принимает обычные аргументы и при необходимости обращается к API или Store. Чистое вспомогательное преобразование, например нормализацию записи, выноси в helper.
- **Entity** описывает предметную область, например тип сериала. Добавляй Store у владельца сущности, когда нескольким частям приложения нужно независимо читать и менять одни и те же клиентские данные.
- **Router** живёт в `apps/web/src/app/router/`. Его Presenter читает путь, а компонент `Router` выбирает экран из `app/pages/`. Приложение подключает `Router` через `./router`.

## Куда положить код

- **Компонент** — в папку с тем же именем в PascalCase: `Button/Button.tsx`. Рядом размещай нужные ему `usePresenter.ts`, `styles.module.css`, `types.ts` и `store.ts`. Через `index.ts` экспортируй только публичную часть.
- **Общий код** — у ближайшего общего владельца. Код двух дочерних компонентов `Results` остаётся в `Results/`. Общие для нескольких экранов UI-компоненты идут в `src/app/components/`, технические функции — в `src/app/utils/`.
- **Логика компонента** — в подпапке категории с первого файла. Например, первую Task клади в `logic/tasks/selectGenre.ts`, первый helper — в `logic/helpers/normalizeQuery.ts`. Все категории и примеры перечислены в [общем правиле структуры SA](sa/sa-structure.md).
- **Task, helper или util** — одна функция на файл. Имя файла совпадает с именем функции, например `loadSearchPage.ts`.
- **API** — эндпоинт вызывает `request<T>()` из `@/app/utils/request` и возвращает данные в формате сервиса. Task преобразует их в модель приложения, с которой работает Presenter.
- **Общие компоненты** импортируй из публичного модуля по алиасу, например `@components/Button`. Алиас не используется для обращения к приватным стилям и логике. Скелетоны (разметка, количество и размеры заглушек) размещай рядом с компонентом-владельцем; размеры задавай в CSS Module.
- **Импорты** — родитель подключает дочерний компонент через его `index.ts`. Между соседними ветками передавай данные вниз через пропсы, а события вверх через колбэки общего родителя. Общую функцию или тип переноси к этому родителю. Импорты родителя и внутренних файлов соседней ветки запрещены.

## Пример: поиск и фильтрация

1. Presenter экрана передаёт критерии в Task `selectGenre`. Тот сохраняет название, меняет жанр и возвращает страницу 1. Выбор «Все» снимает ограничение по жанру.
2. При смене названия, жанра или страницы Presenter загружает нужную выдачу. Task `loadSearchPage` получает критерии, сигнал отмены и операцию HTTP `searchShows` сгенерированного клиента. Сервер собирает жанры всей выдачи, фильтрует сериалы и возвращает страницу из трёх карточек.
3. Загрузку показывай по отдельному флагу, ошибку — по ошибке запроса без данных, пустую выдачу — после ответа с пустым массивом карточек. Подсказку для пустой выдачи выбирай по применённому жанру. Не объединяй эти факты в строковый статус.
4. Выбранный отсутствующий жанр остаётся доступен в интерфейсе. Прокрутка, фокус и повтор загрузки принадлежат Presenter. Настройки языка и темы применяют правила через браузерные адаптеры.
5. Поиск и экран избранного получают снимок и обработчики через props из Presenter роутера. Общие сценарии лежат в `app/logic/favorites/tasks/`. Сервер определяет пользователя по сессионной cookie и хранит снимки по email в памяти процесса. Выход завершает сессию. Подборка доступна при повторном входе до перезапуска API.
