# Архитектура приложения

## Роли VIPER

- **View** (`Name.tsx`) рисует JSX по пропсам. Если нужны состояние или обработчики, получает их из `usePresenter(props)`.
- **Presenter** (`usePresenter.ts`) управляет состоянием UI, эффектами, SWR и подписками на Store. Обрабатывает события View, вызывает задачи и выполняет переходы.
- **Interactor** (task) выполняет один бизнес-сценарий. Это обычная функция TypeScript: принимает данные, вызывает эндпоинты и при необходимости обращается к Store напрямую. Её можно вызвать вне React, без хуков и роутера.
- **Entity** описывает предметную область, например тип сериала. Если сущности нужен Store, держи его у владельца этих данных.
- **Router** представлен папкой экрана, например `src/app/SearchPage/`. Экраны и провайдеры собирает `App.tsx`; параметры маршрута читает Presenter.

## Куда положить код

- **Компонент** — в папку с тем же именем в PascalCase: `Button/Button.tsx`. Рядом размещай нужные ему `usePresenter.ts`, `styles.module.css`, `types.ts` и `store.ts`. Через `index.ts` экспортируй только публичную часть.
- **Общий код** — у ближайшего общего владельца. Код двух дочерних компонентов `Results` остаётся в `Results/`. Общие для нескольких экранов UI-компоненты идут в `src/app/components/`, технические функции — в `src/app/utils/`.
- **Логика компонента** — в его `logic/`. Первый файл категории клади прямо туда; когда появляется второй, перенеси оба в подпапку: `tasks/` для сценариев, `hooks/` для хуков, `helpers/` для чистых функций, `utils/` для служебных функций с возможными побочными эффектами, `api/` для эндпоинтов, `types/` для внутренних типов.
- **Task, helper или util** — одна функция на файл. Имя файла совпадает с именем функции, например `searchShows.ts`. Эндпоинты вызывают `request<T>()` из `@/app/utils/request`.
- **Импорты** — родитель подключает дочерний компонент через его `index.ts`. Дочерний компонент не импортирует родителя или внутренние файлы соседней ветки.
