# Архитектура приложения

## Роли VIPER

- **View** (`Name.tsx`) рисует JSX по пропсам. Если нужны состояние или обработчики, получает их из `usePresenter(props)`.
- **Presenter** (`usePresenter.ts`) готовит данные и обработчики для View, запускает эффекты и выполняет переходы. Состояние UI держи в Presenter ближайшего общего владельца. Результаты запросов кешируй через SWR.
- **Interactor** (task) реализует действие пользователя или правило продукта, например фильтрацию по жанру. Task вызывается вне React, принимает обычные аргументы и при необходимости обращается к API или Store. Чистое вспомогательное преобразование, например нормализацию записи, выноси в helper.
- **Entity** описывает предметную область, например тип сериала. Добавляй Store у владельца сущности, когда нескольким частям приложения нужно независимо читать и менять одни и те же клиентские данные.
- **Router** представлен папкой экрана, например `src/app/SearchPage/`. Экраны и провайдеры собирает `App.tsx`; параметры маршрута читает Presenter.

## Куда положить код

- **Компонент** — в папку с тем же именем в PascalCase: `Button/Button.tsx`. Рядом размещай нужные ему `usePresenter.ts`, `styles.module.css`, `types.ts` и `store.ts`. Через `index.ts` экспортируй только публичную часть.
- **Общий код** — у ближайшего общего владельца. Код двух дочерних компонентов `Results` остаётся в `Results/`. Общие для нескольких экранов UI-компоненты идут в `src/app/components/`, технические функции — в `src/app/utils/`.
- **Логика компонента** — в его `logic/`. Первый файл категории клади прямо туда; когда появляется второй, перенеси оба в подпапку: `tasks/` для сценариев, `hooks/` для хуков, `helpers/` для чистых функций, `utils/` для служебных функций с возможными побочными эффектами, `api/` для эндпоинтов, `types/` для внутренних типов.
- **Task, helper или util** — одна функция на файл. Имя файла совпадает с именем функции, например `searchShows.ts`.
- **API** — эндпоинт вызывает `request<T>()` из `@/app/utils/request` и возвращает данные в формате сервиса. Task преобразует их в модель приложения, с которой работает Presenter.
- **Импорты** — родитель подключает дочерний компонент через его `index.ts`. Между соседними ветками передавай данные вниз через пропсы, а события вверх через колбэки общего родителя. Общую функцию или тип переноси к этому родителю. Импорты родителя и внутренних файлов соседней ветки запрещены.

## Пример: поиск и фильтрация

1. Presenter компонента `Results` передаёт `searchShows` в SWR как загрузчик. Task вызывает `fetchShows`, преобразует записи TVmaze в `Show[]` и возвращает их в кеш SWR.
2. При выборе жанра `Results` вызывает колбэк `selectGenre`. Presenter экрана `SearchPage` обновляет жанр и передаёт его обратно через пропсы. Presenter `Results` вызывает `filterShows` для уже загруженных сериалов без нового HTTP-запроса.
