# Правила проекта

- Пиши код на TypeScript со строгой проверкой типов. Сохраняй React StrictMode в корневом компоненте `src/app/App.tsx`.
- Используй Rsbuild для сборки, Axios для HTTP и SWR для кеширования запросов.
- Для переходов между экранами используй View Transitions API.
- Добавляй текст интерфейса в английский и русский словари i18next. Английский доступен при запуске, русский загружается по требованию.
- Роли VIPER, структуру компонентов и границу между локальным и общим кодом определяй по [правилам архитектуры](architecture.md).
- Ограничивай каждый написанный вручную текстовый файл 120 строками, включая комментарии и пустые строки. При превышении раздели файл по ответственности. Сгенерированные pnpm lock-файл и навыки OpenSpec обслуживают их инструменты.
- Форматируй через `pnpm format`. Проверяй формат, лимит строк, линтинг и типы через `pnpm check`.
- Отделяй вызов React-хука пустой строкой от предыдущей и следующей инструкции. Это относится и к присваиванию результата хука. На границе блока пустая строка не нужна.
- Оставляй одну пустую строку перед `return`, если в том же блоке есть предыдущая инструкция. Комментарий к `return` оставляй рядом с ним.
- Пиши тела `if`, `else` и циклов в фигурных скобках, даже для одной инструкции. Тело блока начинается с новой строки. Допускается `else if`.
- Используй только один уровень тернарного оператора. Для нескольких решений используй обычные условия, именованные значения или таблицу соответствий.
- Дожидайся промиса через `await`, возвращай его вызывающему коду или обрабатывай отклонение. Намеренный запуск без ожидания обозначай `void`, в том числе внутри обработчиков событий.
- В эндпоинтах вызывай `request<T>({ url, ... })` из `@/app/utils/request`. Только `src/app/utils/request.ts` отправляет HTTP-запросы через Axios и дожидается ответа внутри `try/catch`, сохраняя исходную ошибку в `cause`. Oxlint отклоняет прямое использование клиента Axios, браузерного `fetch` и `XMLHttpRequest` в остальном коде приложения. Типы Axios и именованные функции проверки ошибок, например `isAxiosError`, разрешены.
- Общие уведомления об ошибках API задавай в `SWRConfig.onError` у `AppSWRConfig`. Для HTTP 429 показывай предупреждение о лимите запросов, для остальных ошибок — общее уведомление.
- Порядок групп импортов — React и React DOM, сторонние библиотеки, внутренние модули (включая `@/`), `import type`, стили. Выноси типы из смешанных импортов в отдельные объявления `import type`. В каждой группе сортируй пути по алфавиту. Между непустыми группами оставляй одну пустую строку, перед кодом после импортов — две.
- Новые правила редактора, форматирования и разработки храни в этом репозитории.
