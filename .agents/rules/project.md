# Правила проекта

- Пиши код на TypeScript со строгой проверкой типов. Сохраняй React StrictMode в точке входа.
- Используй Rsbuild для сборки, Axios для HTTP и SWR для кеширования запросов.
- Добавляй текст интерфейса в английский и русский словари i18next. Английский доступен при запуске, русский загружается по требованию.
- Структуру компонентов, имена файлов и направления импортов определяй по [правилам архитектуры](architecture.md).
- Ограничивай каждый написанный вручную текстовый файл 120 строками, включая комментарии и пустые строки. При превышении раздели файл по ответственности. Сгенерированные pnpm lock-файл и навыки OpenSpec обслуживают их инструменты.
- Форматируй через `pnpm format`. Проверяй формат, лимит строк, линтинг и типы через `pnpm check`.
- В эндпоинтах вызывай `request<T>({ url, ... })` из `@shared/utils/request`. Только `src/shared/utils/request.ts` отправляет HTTP-запросы через Axios и дожидается ответа внутри `try/catch`, сохраняя исходную ошибку в `cause`. Oxlint отклоняет прямое использование клиента Axios, браузерного `fetch` и `XMLHttpRequest` в остальном коде приложения. Типы Axios и именованные функции проверки ошибок, например `isAxiosError`, разрешены.
- Общие уведомления об ошибках API задавай в `SWRConfig.onError` у `ApiProvider`. Для HTTP 429 показывай предупреждение о лимите запросов, для остальных ошибок — общее уведомление.
- Порядок групп импортов — React и React DOM, сторонние библиотеки, внутренние модули (включая `@shared/`), `import type`, стили. Выноси типы из смешанных импортов в отдельные объявления `import type`. В каждой группе сортируй пути по алфавиту. Между непустыми группами оставляй одну пустую строку, перед кодом после импортов — две.
- Новые правила редактора, форматирования и разработки храни в этом репозитории.
