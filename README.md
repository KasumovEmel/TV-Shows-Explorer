# TV Shows Explorer

Учебный проект курса Simple Architecture. Season One ищет сериалы по русскому и английскому названию. При открытии видно только поле. После паузы в 300 мс или по Enter приложение получает полную выдачу через Axios; SWR кеширует её по запросу.

## Дизайн поиска сериалов

[Season One — макеты и состояния](docs/design/README.md) · [Альбом в PDF](docs/design/series-search.pdf) · [Справочник компонентов](docs/design/components.md) · [Токены](docs/design/tokens.json).

Введите **Breaking Bad** или **Во все тяжкие**. Браузер запрашивает [поиск TVmaze](https://www.tvmaze.com/api#show-search) прямо со страницы. Русское название найдётся, если оно есть в базе TVmaze. Порядок результатов задаёт API. Жанры доступны сразу для всей выдачи, прокрутка добавляет по три сериала, а номер страницы переводит к выбранной группе.

Поиску нужен доступ к интернету. Для публикации достаточно раздать содержимое `dist/` по HTTP, в том числе из подкаталога. Семь сериалов из макета используются в браузерных тестах для проверки страниц и фильтров.

[Оболочка Season One](openspec/changes/archive/2026-11-13-design-app-shell/design.md) следует системной теме и возвращает пользователя в пустое поле поиска после сбоя рендера.

Общие элементы находятся в [Shared/components](src/Shared/components): `Brand`, `Icon`, `Button`, `SearchField`, `GenreChip`, `ShowCard` и `NotificationProvider`. Новый экран может вызвать `useNotify()` и передать событие, например `notify({ kind: 'warning' })`. Для собственного текста передай `messageKey` с ключом из обоих словарей. [Правила очереди, закрытия и фокуса](docs/design/system-components.md).

## Запуск

Потребуются Node.js 22.12 или новее и pnpm 12.18.0. Из корня проекта:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Открой адрес, напечатанный Rsbuild. Чтобы использовать закреплённую версию pnpm на машине со старым Corepack, запускай те же команды через npm:

```sh
npx --yes pnpm@12.18.0 install --frozen-lockfile
npx --yes pnpm@12.18.0 dev
```

## Команды

| Команда                                      | Назначение                                                    |
| -------------------------------------------- | ------------------------------------------------------------- |
| `pnpm format`                                | Отформатировать файлы и проверить лимит в 120 строк           |
| `pnpm check`                                 | Проверить формат, лимит строк, линтинг и типы                 |
| `pnpm build`                                 | Проверить типы и собрать приложение в `dist/`                 |
| `pnpm preview`                               | Открыть локальный сервер собранного приложения                |
| `pnpm test`                                  | Проверить поиск, страницы, адаптивность и оболочку в Chromium |
| `pnpm test:shell`                            | Проверить восстановление, темы и уведомления в Chromium       |
| `pnpm exec openspec validate --all --strict` | Проверить спецификации и активные изменения                   |

Перед первым запуском браузерных тестов установи Chromium: `pnpm exec playwright install chromium --only-shell`. Тесты используют отдельную сборку и сохраняют снимки экранов в `test-results/`. В обычной сборке нет кнопок или адресов для вызова тестового сбоя.

## Работа над заданием

Открой папку проекта в VS Code и установи рекомендованные расширения. При сохранении JS/TS расширение Advanced Local Formatters запускает тот же форматтер, что и `pnpm format`. Порядок групп — React → сторонние библиотеки → внутренние модули → `import type` → стили. Форматтер отделяет типы от значений в смешанных импортах. В каждой группе пути сортируются по алфавиту. Между группами остаётся одна пустая строка, перед кодом — две.

Oxc отвечает за диагностику и форматирование остальных файлов. Расширение TypeScript 7 использует локальную версию TypeScript для автодополнения и навигации. Вкладки одноимённых файлов получают подписи по родительской папке, например `Catalog/index`.

Добавляй правила для агентов в `.agents/rules/` отдельными Markdown-файлами. Корневой `AGENTS.md` указывает агентам читать их перед работой.

Для нового задания используй навык `$openspec-propose`, для реализации — `$openspec-apply-change`, для завершённого изменения — `$openspec-archive-change`. Действующие спецификации хранятся в `openspec/specs/`.
